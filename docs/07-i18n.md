# Languages

Three locales: `sq` (default), `en`, `it`. **Italian is out of scope for v1** —
build the system for three, ship with two.

## Routing

Every public route is prefixed: `/sq/...`, `/en/...`, `/it/...`. No unprefixed
routes, no cookie-based redirect on the root domain except a single 302 from
`/` to `/sq`.

Switching locale must keep the user on the same entity. The slug is not
localized — one slug per entity, generated from the Albanian title — so
`/sq/prona/vila-me-pishine-dhermi` becomes `/en/prona/vila-me-pishine-dhermi`.

This is a deliberate trade: localized slugs would score marginally better in
English search, and would cost a slug-per-locale table plus redirect handling on
every rename. Not worth it at this size.

Route segments themselves stay Albanian in all locales (`/en/prona/...`, not
`/en/properties/...`). One route tree, no translated path map.

## Content translation

Payload field-level localization. `localized: true` on the field, and Payload
stores one value per locale with independent versions.

Localized: `title`, `description`, `tagline`, `about`, article `title`, `body`,
`excerpt`, SEO `metaTitle` and `metaDescription`, area `description`.

**Never localized**: price, currency, areaSqm, rooms, bedrooms, floor,
orientation, coordinates, dates, status, slugs, company names, project names,
person names, addresses, phone numbers, reference codes.

If you localize a number, you have introduced a bug where the Albanian and
English pages disagree about the price.

## Machine translation workflow

Not in v1. When it arrives: a draft is created in `sq`, an admin action fills
`en` and `it` as drafts, and each locale is published separately. The
architecture above already supports this — do not build the automation now, and
do not build anything that would block it.

## UI strings

`next-intl`, messages in `messages/sq.json`, `messages/en.json`. Keys are
dot-namespaced by feature (`search.filters.priceMin`). No hardcoded Albanian
text inside components.

## Formatting

Prices: `€250,000` with thin-space grouping, same format in all locales — the
client's market reads European format regardless of interface language. Dates:
`Intl.DateTimeFormat` with the active locale.
